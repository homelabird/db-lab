실습 가이드

같은 주문으로 정상 동작과 장애 상황을 비교해 보세요.

  1. 주문 만들기 — 주문 화면에서 가짜 상품을 저장합니다.
  2. 저장소 비교하기 — 상품을 열고 저장소 비교에서 캐시와 검색 반영을 확인합니다.
  3. 장애 전후 확인하기 — 아래 터미널 명령으로 한 번에 하나의 조건만 변경합니다.
데이터 흐름 이해하기
쓰기: API → MariaDB [주문 + outbox] → worker → Kafka → worker → Elasticsearch
상세 읽기: API → Redis HIT / MISS → MariaDB → Redis (TTL)
상태 변경: MariaDB 버전 증가 → 검색 반영 · 캐시 무효화
시나리오 자동 실행

아래 명령은 터미널에서 실행합니다. seed는 요청 계획을 고정하며, 실제 지연·스레드 순서까지 같게 만들지는 않습니다. 결과는 reports/simulations에 기록됩니다.

./all.sh mvp simulate list
./all.sh mvp simulate plan kafka-outage --seed 42
./all.sh mvp simulate run baseline --seed 42 --yes
./all.sh mvp simulate run kafka-outage --seed 42 --yes
./all.sh mvp simulate run row-lock --seed 42 --yes
./all.sh mvp simulate run version-race --seed 42 --yes
# 중단된 실습의 복원 마커가 남았을 때만:
./all.sh mvp simulate recover --yes

plan은 DB를 변경하지 않습니다. run은 합성 주문을 남기고 지정한 장애를 실제로 주입합니다. 웹에서 장애 명령은 실행하지 않습니다.

터미널에서 장애·교체 실습

한 번에 하나만 변경한 뒤 같은 주문으로 비교하세요. 웹 화면은 호스트 명령을 실행하지 않습니다.

./all.sh mvp stop kafka --yes         # 주문은 저장, outbox 증가
./all.sh mvp resume kafka             # 전송 재개 후 검색 반영 확인
./all.sh mvp stop redis --yes         # 일반 조회가 MariaDB로 우회
./all.sh mvp resume redis
./all.sh mvp experiment redis-spare --yes       # 별도 Redis로 연결 대상 교체
./all.sh mvp experiment bad-db-password --yes   # API만 잘못된 DB 암호 사용
./all.sh mvp experiment fresh-search --yes      # 기존 인덱스를 보존하고 새 인덱스 사용
./all.sh mvp rebuild-search --yes               # MariaDB 원본으로 현재 검색 인덱스 재구축
./all.sh mvp experiment normal --yes           # 앱 연결 설정 복원
./all.sh mvp smoke                             # 실제 주문→검색 경로 확인

normal은 앱 설정만 복원합니다. stop한 DB는 resume으로 별도 시작하세요. 컨테이너 재생성과 빈 데이터 저장소로 교체하는 것은 다릅니다.

조회 방식 안내

일반 조회는 Redis 캐시를 먼저 확인하고, 실패하면 MariaDB로 우회합니다. 원본 조회는 MariaDB를 읽고 캐시도 채웁니다. 읽기 전용 대조는 캐시를 변경하지 않습니다. TTL은 캐시 저장 시점 기준이며 저장소 대조는 원자적 스냅샷이 아닙니다.
